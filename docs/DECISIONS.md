# Decisions

Choices not dictated by `docs/BUILD_PROMPT.md`. Newest at the bottom.

1. **Rates in basis points.** Tax, deposit, discount percent, markup percent are integers
   (`825` = 8.25%), so no floats anywhere in money math.
2. **Combined quantities by design key.** Lines combine for quantity breaks when their full set
   of imprints is identical (same location, method, colors, underbase, specialty, size). Lines
   that share only one imprint (same front, different back) do not combine. Simple and
   predictable; can be refined per imprint later.
3. **Screens are counted per unique design, not per line.** Three shirt colors with the same
   3-color front need 3 screens, not 9. Underbase counts as a screen.
4. **Discount is allocated pro-rata** across taxable and non-taxable amounts before tax.
5. **Rush applies after discount** and is taxable when the underlying items are (pro-rata).
6. **Shipping is added after tax** and is untaxed unless its fee is marked taxable.
7. **Expired exempt certificate**: the quote is still treated as exempt (the flag is the
   user's decision), but a prominent warning shows on the quote and a one-click toggle charges
   tax. Nothing is silently changed.
8. **Quantity below the first matrix break** is priced at the first break and triggers the
   below-minimum fee if one is set.
9. **Rounding to $0.05 / $0.25** rounds the unit price to the nearest step, half up.
10. **Revisions** keep the base number: `Q-1001` → `Q-1001-R2`. The old revision becomes
    `superseded` and read-only. Revisions don't consume a new number.
11. **Overdue and Expired** are computed from dates. Expired is also persisted by a sweep so
    reports and filters stay simple; Overdue is never stored.
12. **Garment snapshot on line items.** Catalog edits never change existing quotes or invoices.
13. **Branch**: work is pushed to `claude/busy-turing-2vebl1`. On a brand-new repo the first
    pushed branch becomes GitHub's default branch; rename or set `main` as you like.

## Phase 1

14. **Matrix grids are stored as JSON** (`breaks`, `columns`, `prices`) on the matrix row
    rather than in three normalized tables. The grid is always read and saved whole, and zod
    validates its shape (ascending breaks/columns, prices sized breaks × columns).
15. **Migrations follow the phases.** `001_init.sql` holds the Phase 1 tables; quote, invoice
    and payment tables arrive in the migration for their phase, once their design is exercised.
16. **Archive, don't delete.** Customers, garments, matrices, fees and inks are archived and can
    be restored ("Show archived"). The only hard delete is a customer's extra contact, behind a
    confirmation.
17. **Sample data loses its "Sample" badge once edited** (matrix, rules, fee). The dashboard's
    getting-started list uses that to tell whether pricing has been made your own.
18. **Garments are unique by brand + style number** among non-archived garments. Duplicating
    appends "copy" to the style number.
19. **CSV import** groups rows by brand + style (or name), keeps the *highest* cost seen per
    size group, fills a group with no cost from the next smaller group, guesses swatches and
    categories from names, and is all-or-nothing (one invalid garment rolls the import back).
20. **"Dark" garment colors** (which get an underbase suggested) are colors with relative
    luminance below 0.18. Each color's flag can be changed by hand in the garment editor.
21. **No native rebuild for SQLite.** better-sqlite3 13 ships Node-API prebuilt binaries that
    load in Electron unchanged, so `electron-rebuild` (which downloads Electron headers) is not
    needed. `npmRebuild: false` in `electron-builder.yml`.
22. **Markup multipliers are stored × 1000** (1800 = ×1.8). Switching between percent and
    multiplier converts the tiers so the effective markup stays the same.
23. **SMTP password**: if the OS has no secure storage (some Linux setups), Inkwell refuses to
    save the password rather than storing it in plain text.
24. **Restore** validates the file (is an Inkwell DB, passes `quick_check`, not from a newer
    schema), saves a `before-restore` backup, swaps the DB file and relaunches. Backups cover
    the database only; the README says to copy the data folder to include attachments.
25. **Phase 1 dashboard** is a getting-started checklist plus counts. The real dashboard is
    Phase 4. Quotes and Invoices nav items show a "coming in Phase N" page.
26. **UI components are written in-repo** (shadcn-style, on Radix primitives and Tailwind) rather
    than generated by the shadcn CLI, to keep the dependency list short.
27. **Forms use the app's own validation** (`noValidate`), so the shared zod messages show
    inline instead of the browser's tooltip.
