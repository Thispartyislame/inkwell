# Decisions

Choices not dictated by `docs/BUILD_PROMPT.md`. Newest at the bottom.

1. **Rates in basis points.** Tax, deposit, discount percent, markup percent are integers
   (`825` = 8.25%), so no floats anywhere in money math.
2. **Combined quantities by design key.** Lines combine for quantity breaks when their full set
   of imprints is identical (same location, method, colors, underbase, specialty, size). Lines
   that share only one imprint (same front, different back) do not combine. Simple and
   predictable; can be refined per imprint later.
3. **Screens are counted per unique design, not per line.** Three shirt colors with the same
   3-color front need 3 screens, not 9. Underbase counts as a screen.
4. **Discount is allocated pro-rata** across taxable and non-taxable amounts before tax.
5. **Rush applies after discount** and is taxable when the underlying items are (pro-rata).
6. **Shipping is added after tax** and is untaxed unless its fee is marked taxable.
7. **Expired exempt certificate**: the quote is still treated as exempt (the flag is the
   user's decision), but a prominent warning shows on the quote and a one-click toggle charges
   tax. Nothing is silently changed.
8. **Quantity below the first matrix break** is priced at the first break and triggers the
   below-minimum fee if one is set.
9. **Rounding to $0.05 / $0.25** rounds the unit price to the nearest step, half up.
10. **Revisions** keep the base number: `Q-1001` → `Q-1001-R2`. The old revision becomes
    `superseded` and read-only. Revisions don't consume a new number.
11. **Overdue and Expired** are computed from dates. Expired is also persisted by a sweep so
    reports and filters stay simple; Overdue is never stored.
12. **Garment snapshot on line items.** Catalog edits never change existing quotes or invoices.
13. **Branch**: work is pushed to `claude/busy-turing-2vebl1`. On a brand-new repo the first
    pushed branch becomes GitHub's default branch; rename or set `main` as you like.

## Phase 1

14. **Matrix grids are stored as JSON** (`breaks`, `columns`, `prices`) on the matrix row
    rather than in three normalized tables. The grid is always read and saved whole, and zod
    validates its shape (ascending breaks/columns, prices sized breaks × columns).
15. **Migrations follow the phases.** `001_init.sql` holds the Phase 1 tables; quote, invoice
    and payment tables arrive in the migration for their phase, once their design is exercised.
16. **Archive, don't delete.** Customers, garments, matrices, fees and inks are archived and can
    be restored ("Show archived"). The only hard delete is a customer's extra contact, behind a
    confirmation.
17. **Sample data loses its "Sample" badge once edited** (matrix, rules, fee). The dashboard's
    getting-started list uses that to tell whether pricing has been made your own.
18. **Garments are unique by brand + style number** among non-archived garments. Duplicating
    appends "copy" to the style number.
19. **CSV import** groups rows by brand + style (or name), keeps the *highest* cost seen per
    size group, fills a group with no cost from the next smaller group, guesses swatches and
    categories from names, and is all-or-nothing (one invalid garment rolls the import back).
20. **"Dark" garment colors** (which get an underbase suggested) are colors with relative
    luminance below 0.18. Each color's flag can be changed by hand in the garment editor.
21. **No native rebuild for SQLite.** better-sqlite3 13 ships Node-API prebuilt binaries that
    load in Electron unchanged, so `electron-rebuild` (which downloads Electron headers) is not
    needed. `npmRebuild: false` in `electron-builder.yml`.
22. **Markup multipliers are stored × 1000** (1800 = ×1.8). Switching between percent and
    multiplier converts the tiers so the effective markup stays the same.
23. **SMTP password**: if the OS has no secure storage (some Linux setups), Inkwell refuses to
    save the password rather than storing it in plain text.
24. **Restore** validates the file (is an Inkwell DB, passes `quick_check`, not from a newer
    schema), saves a `before-restore` backup, swaps the DB file and relaunches. Backups cover
    the database only; the README says to copy the data folder to include attachments.
25. **Phase 1 dashboard** is a getting-started checklist plus counts. The real dashboard is
    Phase 4. Quotes and Invoices nav items show a "coming in Phase N" page.
26. **UI components are written in-repo** (shadcn-style, on Radix primitives and Tailwind) rather
    than generated by the shadcn CLI, to keep the dependency list short.
27. **Forms use the app's own validation** (`noValidate`), so the shared zod messages show
    inline instead of the browser's tooltip.

## After Phase 1

28. **Margin pricing.** Garment markup has a third mode, *target margin on the sell price*:
    sell = cost ÷ (1 − margin), rounded half up to the cent. Tiers work the same as the other
    modes and margins must be below 95%. Switching modes converts each tier so prices don't
    change (+100% markup = ×2.0 = 50% margin). Added in migration `002_margin_markup.sql`,
    which rebuilds the one-row `pricing_rules` table because SQLite can't alter a CHECK.
29. **Cost vs sell is shown for the blank garment only**: marked-up price plus the size
    upcharge, before decoration. Margin = (sell − cost) ÷ sell. Shown in the catalog list, the
    garment editor and a preview table in Pricing rules; internal only. Full job cost and margin
    (with printing) comes with the quote builder.

## Phase 2

30. **Quotes are saved whole.** The builder edits one document (lines, sizes, imprints, fees)
    and autosaves it 600 ms after the last change; the save replaces the child rows in one
    transaction. Child rows carry stable `uid`s so the editor keeps focus and state across saves.
    The activity log records at most one "edited" entry per 10 minutes.
31. **Prices freeze when a quote leaves draft.** Each save stores the pricing configuration it
    used (rules, matrices, rounding, tax default, the customer's exempt status). Drafts always
    reprice with the current configuration; sent, approved, declined and expired quotes keep the
    configuration they were sent with, so later pricing changes never alter them. To change a
    non-draft quote, use Revise.
32. **Revisions** share the root number (`Q-1001`, `Q-1001-R2`, …), don't consume a new quote
    number, start as drafts with today's date, and copy the attachments. The replaced revision
    becomes "Revised" (`superseded`) and is hidden from the quotes list by default.
33. **Automatic fees come from the pricing rules**, not from fee presets: screens (per unique
    design: lines with identical imprints share screens), digitizing (per new embroidery design),
    small-order fee, and rush. Each can be waived per quote. Their taxability follows the matching
    fee preset (Screen Setup, Digitizing, Rush). Presets of those kinds can still be added by
    hand for extra charges.
34. **Matrix choice per imprint**: the imprint's own matrix if picked, else the customer's
    default matrix when it is for the same method, else the default matrix for the method. Pick
    the contract-print matrix on imprints for customer-supplied garments.
35. **Customer-supplied garments** have no garment price and no size upcharge, and count as $0
    cost in the profit estimate.
36. **Quantity below the first break** is priced at the first break with a note; the small-order
    fee applies separately when the whole quote is under the minimum.
37. **Expired exemption certificate**: tax stays off, a red warning shows in the totals, and
    "Charge tax anyway" turns tax on for that quote.
38. **Quote PDFs** are rendered by loading the same React template the preview uses into a hidden
    window and printing it (Letter, 0.5" margins, "Page X of Y" footer). A copy of every
    generated PDF is kept in `pdfs/` in the data folder. Drafts print without a watermark, since
    they are usually exported just before being sent; approved/declined/expired/revised quotes
    get a faint stamp.
39. **Keyboard shortcuts** (Ctrl/Cmd+N new quote, Ctrl/Cmd+K search) are handled by the window;
    the menu only displays them, so they can't fire twice.
40. **Attachments** accept images, PDF, AI, EPS, PSD and TIFF up to 100 MB each. Only images
    can be placed on the PDF. Files are copied into the data folder; deleting one never touches
    the original.

## Phase 3

41. **Only approved quotes convert**, and only once while the invoice is live. Voiding the
    invoice unlinks it so the quote can be invoiced again. A converted quote can't be revised.
42. **Converted invoices keep the quote's pricing** (the frozen rules and matrices it was
    approved with), even while you edit them before sending, so adding two shirts uses the
    quoted per-piece price. "Reprice with current pricing" switches a draft to today's pricing.
    Blank invoices follow current pricing until sent.
43. **Invoices lock when sent**, not when paid. A deposit often arrives before the final counts
    are known, so payments alone don't lock an invoice. To change a sent invoice, void it and
    make a new one. Void is refused while live payments exist.
44. **Status is computed from money**: any payment → Partially paid; paid ≥ total → Paid;
    otherwise Sent (if sent) or Draft. Overdue is never stored: an unpaid sent invoice past its
    due date shows as Overdue. Overpayment is allowed and shows as a credit.
45. **Deposits** are payments recorded against a quote (sent, approved, expired or draft). They
    move to the revised quote on Revise and to the invoice on conversion, keeping their receipt
    numbers. Payments are never deleted, only voided (kept in history, crossed out).
46. **Due date** = invoice date + the payment terms in Settings (Net N; due on receipt = same
    day). Terms are stored as text on the invoice and can be edited per invoice.
47. **Receipt numbers** (R-1001…) are allocated per payment, so every payment has a printable
    receipt.
48. **Customer balance** = sum of balances of sent / partially paid / paid invoices (not drafts
    or void); a negative total means the customer has a credit.
49. **Email** goes out through your own SMTP account; nothing else touches the network. The From
    name defaults to the shop name, replies go to the shop email. Sending marks a draft quote or
    unsent invoice as Sent (can be unticked). Without SMTP, Inkwell saves the PDF, opens its
    folder and copies "Subject + message" to the clipboard.
50. **SMTP password** uses Electron's async `safeStorage` API (the synchronous one is
    deprecated). On Linux this needs a running keyring (GNOME Keyring / KWallet); without one
    the password isn't saved and the no-SMTP fallback is used.
51. **Document vocabulary**: quotes say "Prepared for", invoices "Bill to", receipts "Received
    from". Invoices show "how to pay" only while a balance is due.

## Phase 4

52. **Sales** in reports and on the dashboard = issued invoices (not draft, not void) by invoice
    date, before tax and shipping: subtotal − discount + rush. **Collections** = payments by the
    date received. Archived invoices still count; they were real sales.
53. **Sales tax report**: gross = net sales + shipping; taxable = the taxable base the invoice
    charged tax on; exempt = all sales to customers whose exemption applied; non-taxable = the
    rest (untaxed fees and shipping). Tax is reported on the invoice date (accrual basis).
    Invoices saved before Phase 4 get their exempt flag inferred from the pricing snapshot.
54. **Win rate** = approved ÷ (approved + declined + expired) for quotes dated in the range,
    counting only the latest revision. Sent quotes past their expiration count as expired.
55. **Production** stages live on the job: an approved quote starts at "Awaiting art", and the
    stage moves to the invoice on conversion. Invoices made from scratch join the board when you
    pick a stage. Finished jobs ("Picked up / shipped") stay visible for 30 days.
56. **Garment order list** preselects jobs still before "Garments ordered", leaves out
    customer-supplied garments, and estimates cost from each line's garment snapshot. "Mark as
    ordered" only moves jobs forward.
57. **Shortcuts**: Ctrl/Cmd+K opens the command palette (the top search bar stays for the mouse);
    Ctrl/Cmd+P opens the PDF on a quote or invoice page.
58. **Packaging**: unsigned builds; the NSIS installer lets you pick the folder and never deletes
    your data on uninstall; macOS dmg for Intel and Apple silicon; no auto-update (`publish:
    null`), since that would contact a server.

## Phase 5

59. **Licensing for separations**: paper.js (MIT), paperjs-offset (MIT), pdf.js (Apache-2.0).
    No copyleft code is bundled. EPS uses Inkscape or Ghostscript only if the user has
    installed them; Inkwell runs them as separate programs and doesn't ship them.
60. **Units**: all separation geometry is in points (1/72″). SVG size comes from its
    width/height units (unitless = CSS px at 96/in); files without a size get a warning and
    the print width can be set by hand. Film pages use 1 SVG unit = 1 pt with page size in
    inches, so 100% is exact (checked by rasterizing an exported film and measuring).
61. **Visible-area model**: shapes are painted in file order and each knocks out what is
    under it, which is what the art looks like. Dropped colors still knock out (the shirt
    shows through there). Overprint colors don't knock out what's below them.
62. **Trap** spreads every color printed after the first by the same amount; the first ink
    and the underbase are never spread. **Choke** shrinks the underbase.
63. **Highlight white** moves near-white inks to print last (after the colors) instead of
    adding an extra plate.
64. **Halftones (beta)**: a rotated dot grid at the chosen LPI; dot area = ink coverage,
    taken from the gradient color's lightness relative to its darkest stop, or from a fill's
    opacity. Dots are kept whole (no clipping at edges) and capped at 150,000 per plate.
65. **PNG films** are rendered from the same SVG and thresholded to pure black/white; very
    large pages lower the dpi to stay under browser canvas limits (a notice says so).
66. **The paper.js core build** is used in the app: the full build includes a script compiler
    that needs `eval`, which the app's Content-Security-Policy blocks.
67. **Installers are built by GitHub Actions** on a version tag (also publishes a GitHub
    Release) or a manual run. The Windows job proves install and uninstall work. The NSIS
    uninstaller asks whether to delete `%APPDATA%\Inkwell` (default: keep), never during
    updates or silent uninstalls.
